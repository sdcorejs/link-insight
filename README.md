# SdCoreJS Link Insight

SdCoreJS Link Insight is a Chrome Extension (Manifest V3) for Google Chat. Hover over a
supported Jira or Confluence link for 500 ms and the extension shows a popover containing
exactly three short bullets generated by Google Gemini.

This MVP uses Bring Your Own Key (BYOK): there is no backend, the Gemini API key stays in
`chrome.storage.local`, and only the background service worker can read it. Atlassian content is
deterministic mock data in this release; no Jira or Confluence API is contacted.

## Architecture

```text
Google Chat content script
  -> AtlassianLinkProvider via LinkProviderRegistry
  -> LINK_SUMMARY_REQUEST (canonical URL only)
  -> background sender + URL validation
  -> chrome.storage.local key lookup
  -> chrome.storage.session summary cache / in-flight deduplication
  -> MockAtlassianContentFetcher via ContentFetcherRegistry
  -> GeminiSummarizer (native fetch, structured JSON output, store: false)
  -> LINK_SUMMARY_SUCCESS or LINK_SUMMARY_ERROR
  -> DOM-only popover rendering
```

Responsibilities are separated so link recognition, content retrieval, summarization, storage,
messaging, and UI can evolve independently:

- `entrypoints/` contains the WXT background, content-script, and Options Page surfaces.
- `src/link-providers/` recognizes URLs and returns provider-neutral `LinkResource` values.
- `src/content-fetchers/` maps resources to normalized content; the current implementation is mock-only.
- `src/summarizers/` owns Gemini request construction and validated structured-output parsing.
- `src/storage/` owns trusted settings, session cache, TTL, and in-flight deduplication.
- `src/background/` owns the message trust boundary and workflow orchestration.
- `src/ui/` owns delegated hover state and the single reusable popover.
- `src/config/runtime-config.ts` is the single location for Gemini endpoint/model/timeout and cache TTL.

The implementation follows the current stable Gemini Interactions API: `v1/interactions` with
`gemini-3.6-flash`. See [Gemini API versions](https://ai.google.dev/gemini-api/docs/api-versions),
[models](https://ai.google.dev/gemini-api/docs/models), and
[structured outputs](https://ai.google.dev/gemini-api/docs/structured-output).

## Prerequisites

- Node.js 22 or newer (required by the current WXT release).
- npm 10 or newer.
- Google Chrome 102 or newer.
- A Gemini API key created through [Google AI Studio](https://aistudio.google.com/apikey) for live summaries.

No key is required to build or run the automated tests.

## Install dependencies

```bash
npm install
```

The repository uses npm only and commits `package-lock.json` for reproducible installs.

## Development mode

```bash
npm run dev
```

WXT watches the extension sources and launches its development runner. Use the WXT-managed Chrome
profile or load the generated development extension according to the runner output.

## Production build

```bash
npm run build
```

The unpacked Chrome extension is generated at:

```text
.output/chrome-mv3/
```

The build script also validates the generated `manifest.json`, including its MV3 version,
entrypoints, content-script allowlist, Chrome minimum version, permissions, and host permissions.

To create the distributable archive locally:

```bash
npm run zip
```

## Load unpacked in Chrome

1. Run `npm run build`.
2. Open `chrome://extensions` in Google Chrome.
3. Enable **Developer mode**.
4. Select **Load unpacked**.
5. Choose the repository's `.output/chrome-mv3` directory.
6. Click the **SdCoreJS Link Insight** toolbar action to open the Options Page.

Reload the extension from `chrome://extensions` after rebuilding if Chrome is not using the WXT
development runner.

## Configure the Gemini API key

1. Open the Options Page from the toolbar action or the extension details page.
2. Follow the Google AI Studio link and create an API key using Google's current authorization guidance.
3. Paste the key into the password input and select **Save**.
4. The status area reports `Saved locally on this device.` without echoing the key.
5. Use **Clear key** to remove it from this device.

The key is trimmed before storage and is only checked for being non-empty. It is never added to a
URL, synced through `chrome.storage.sync`, sent to the content script, logged, or included in test
fixtures.

## Test in Google Chat

Open either Google Chat surface covered by the manifest:

- `https://chat.google.com/*`
- `https://mail.google.com/chat/*`

Post or receive a message containing links shaped like these examples:

```text
https://example.atlassian.net/browse/DEMO-123
https://example.atlassian.net/wiki/spaces/ENG/pages/123456/Architecture-Guide
```

Hover for less than 500 ms to confirm no request or popover occurs. Hover for at least 500 ms to
see `Loading AI summary...`, followed by three bullets or a structured error. Leaving the link hides
the popover immediately. Hovering the same canonical URL within five minutes uses the background
session cache.

## Mock Atlassian data

This release does not authenticate to Atlassian and never fetches Atlassian APIs, cookies, sessions,
or page DOM. `MockAtlassianContentFetcher` generates deterministic Jira or Confluence content from
the recognized resource type and identifier. The mock includes Jira status/priority/assignee or
Confluence space/author/update metadata so the full background-to-Gemini flow can be exercised.

Atlassian host permissions must be added only when a real authenticated content fetcher is
implemented. They are intentionally absent from this MVP.

## Permissions

| Manifest capability    | Actual value                                                  | Why it is required                                                      |
| ---------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `permissions`          | `storage`                                                     | Stores the BYOK key locally and validated summaries in session storage. |
| `host_permissions`     | `https://generativelanguage.googleapis.com/*`                 | Allows only the background service worker to call Gemini.               |
| Content-script matches | `https://chat.google.com/*`, `https://mail.google.com/chat/*` | Runs delegated hover detection only in Google Chat.                     |
| Minimum Chrome         | `102`                                                         | Required for `storage.local.setAccessLevel` and MV3 `storage.session`.  |

The manifest does not request `activeTab`, `tabs`, `scripting`, `cookies`, `webRequest`, Atlassian
hosts, GitLab hosts, or wildcard network access.

## Privacy and BYOK security limitations

- On service-worker startup and install, local storage is restricted with
  `chrome.storage.local.setAccessLevel({ accessLevel: "TRUSTED_CONTEXTS" })`. Content scripts cannot
  read the key directly.
- The Options Page and background service worker are trusted extension contexts and can read the key.
- `chrome.storage.local` is local extension storage, not a hardware-backed secret vault. Anyone with
  sufficient access to the Chrome profile or operating system may be able to recover local data.
- The installed extension—and therefore a future compromised extension update—can access the key.
  Use a dedicated, restrictable key where Google's current controls allow it, monitor its usage, and
  revoke it if the extension or device is compromised.
- Normalized work-item content is sent directly from the background worker to Google Gemini. Verify
  that this is permitted for the Jira/Confluence data your organization places in Chat.
- The request sets `store: false` because each summary is stateless. Google still processes the
  request under the Gemini API terms and policies.
- Gemini quota and pricing can apply to the user's key. The extension adds no telemetry or analytics.
- Validated summaries live in `chrome.storage.session` for five minutes. The cache stores neither the
  API key nor raw Atlassian content and is cleared when the browser session/extension ends.

## Troubleshooting

### “Set your Gemini API key in the extension options.”

Open the toolbar action, save a non-empty key, then hover the link again. If a key was cleared, the
existing summary cache is not used until a key is configured again.

### Invalid or unauthorized key

The popover reports that Gemini rejected the key for HTTP 401/403 responses. Create or authorize a
key in Google AI Studio according to the current Gemini API-key documentation, save it again, and
retry. The extension does not hard-code a key prefix or format.

### Quota or rate limit

HTTP 429 is shown as a quota/rate-limit error. Review the selected Google Cloud/AI Studio project's
quota and billing, wait for the limit window, then retry.

### Content script does not run

- Confirm the page URL starts with `https://chat.google.com/` or `https://mail.google.com/chat/`.
- Reload the Google Chat tab after initially loading or updating the unpacked extension.
- Confirm the extension is enabled in `chrome://extensions` and has site access for Google Chat.
- Verify that the link is HTTPS and the hostname is exactly `<tenant>.atlassian.net`.

### Service worker errors

Open `chrome://extensions`, find the extension, and select the **service worker** inspection link.
Network failures, timeouts, and Gemini 5xx responses are converted to safe popover messages; the
extension does not intentionally log keys, prompts, URLs, request headers, or raw provider responses.

## Add a GitLab provider later

Adding GitLab should not require changes to `HoverController`, `Popover`, or `GeminiSummarizer`:

1. Implement `GitLabLinkProvider` under `src/link-providers/` to validate HTTPS GitLab URLs and emit
   provider-neutral `LinkResource` objects.
2. Implement a GitLab content fetcher/authentication boundary under `src/content-fetchers/` that maps
   issue, merge-request, and commit payloads into `NormalizedLinkContent`.
3. Register both implementations in the background/content composition roots.
4. Add only the exact GitLab host permissions required by the real fetcher.
5. Add provider, sender/message, fetcher, cache, and security tests before enabling the feature.

Provider and resource types are extensible strings scoped to their implementation; there is no
project-wide Jira-only union or provider-specific branching in the hover UI or Gemini client.

## Scripts and validation

| Command             | Purpose                                                    |
| ------------------- | ---------------------------------------------------------- |
| `npm run dev`       | Start WXT development mode.                                |
| `npm run build`     | Build Chrome MV3 and validate the generated manifest.      |
| `npm run zip`       | Create a production extension archive.                     |
| `npm run lint`      | Run ESLint.                                                |
| `npm run typecheck` | Run strict TypeScript checking without emit.               |
| `npm test`          | Run Vitest unit tests.                                     |
| `npm run check`     | Run lint, typecheck, unit tests, and the production build. |

Automated tests mock `fetch()` and storage. They verify provider URL security, hover timing and stale
responses, Options Page state, trusted storage configuration, background sender/message validation,
Gemini request/response/error handling, cache TTL/deduplication, and source security boundaries.

A live Gemini call is deliberately a manual verification step because this repository contains no
real credentials. Do not report a live call as validated until it has been exercised locally with an
authorized Google AI Studio key.

## Out of scope for this MVP

- Jira or Confluence authentication and real Atlassian API access.
- GitLab authentication, API access, or link support.
- Backend services, user accounts, telemetry, or analytics.
- Chrome Web Store publishing or enterprise-wide key distribution.
- AI-generated HTML rendering.
- Firefox or Safari support.
